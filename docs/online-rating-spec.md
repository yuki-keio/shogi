## 2. 数字は2本立て

| | 値 | 意味 |
|---|---|---|
| 内部レート `rating` | 1000スタート | 普通のイロレーティング。**画面に出さない**。D1 に持つのはこれ |
| **実力値**（画面に出す数字） | 1500スタート | 内部レートから**毎回導出するだけ**。別々には育てない |

```
diff    = internal - 1000
display = max(1400, round(1500 + (diff >= 0 ? 2.3 : 1.4) * diff))
```

- スタートより上は **2.3倍**に引き伸ばす（勝ったときの数字が大きく動いて気持ちいい）
- スタートより下は **1.4倍**に留める（負けが込んでも落ち方が緩やか）
- 起点と倍率はリバーシWeb（`game/rating_service.py`）に合わせてある

変動は `K=32` のイロ。**プラス側は切り上げ・マイナス側は切り捨て**の非対称丸めなので、
どんなに小さくても 0 で止まらず必ず ±1 は動く。

### 下限は 1400（5級のスタートの100点下）

🔴 **止めるのは内部レートのほう**（`INTERNAL_FLOOR = 928`）。実力値の側だけを clamp すると
内部レートが下がり続け、「下限に見えているのに1勝しても数字が戻らない」状態になる。
下限より下の記録（この仕様を入れる前に付いたもの）は、次の1局を指した時点で引き上がる。

下限に貼りついた人が負けると変動幅は 0 になり、結果画面には **「±0」** と出る。

### 負けたときだけ減り幅を抑える（`lossGuard`）

実力値が低い人ほど、負けの減り幅を小さくする。「負けが込むと戻せなくなる」のを防いで、
遊んだぶんだけ少しずつ上がるようにするため。**節はこの3点だけで、あいだは直線。**

| 実力値 | カット率 | 同格相手に1敗 | 1勝 |
|---|---|---|---|
| 1400（下限） | 90% | ±0 | +22 |
| **1500（初期値・5級）** | **70%** | **−7** | **+37** |
| 1600（4級） | 56% | −18 | +37 |
| 1800（2級） | 28% | −28 | +37 |
| **2000（初段）以上** | **0%** | **−37** | **+37** |

- 🔴 **勝ちには掛けない。** 両方に掛けると「上がりにくくする」ことになって狙いが逆になる
- COM戦の半分・同じ相手との連戦の減衰にも、そのうえから同じように掛かる
- 引き分けでも減る側（格下との引き分け）には掛かる
- 表の1敗・1勝は**丸めの都合で ±1 ずれる**ことがある（実力値ちょうどに着地する内部レートが無い帯があるため）
- 🔴 抑えの判定は**実力値**であって、画面に出ている段級位ではない。降格しないので、
  「初段」と表示されている人でも実力値が1900まで落ちていれば14%カットが掛かる

🟢 抑えと釣り合って**止まる**のは、同格相手に5割を切る人だけ（3000局まで回した実測の中央値）。

| 同格相手の勝率 | 20% | 30% | 40% | 45% |
|---|---|---|---|---|
| 落ち着き先 | 1457（5級） | 1580（5級） | 1740（3級） | 1900前後（1級。上へ抜ける人も出る） |

🔴 **勝率5割の人は止まらない。** 2000未満では抑えが必ず上向きに効き、2000以上では抑えが切れて
押し戻す力も消えるので、**2000 が「下からは押し上げるが上へは素通し」の一方通行の弁**になる。
同格相手モデルでは勝率5割ちょうどでも 300局で2282・1000局で2990（中央値）まで上がり続ける。
実際は相手が同格とは限らないぶん緩やかなので、**分布は §3 の表のほうが実態に近い**。

🔴 `internalFromDisplay()` は **COM側の実力値換算専用**。丸めのため往復が一致しないので、
段級位のしきい値判定に使ってはいけない（必ず `rankOf(displayRating(internal))`）。

## 3. 段級位（実力値基準）

| 段級位 | 実力値 | 階級 |
|---|---|---|
| 9級 / 8級 / 7級 | 〜1199 / 1200 / 1300 | 白木 |
| 6級 / **5級**（スタート） / 4級 | 1400 / **1500** / 1600 | 青銅 |
| 3級 / 2級 / 1級 | 1700 / 1800 / 1900 | 銀 |
| 初段 / 二段 / 三段 | 2000 / 2150 / 2300 | 金 |
| 四段 / 五段 / 六段 | 2450 / 2600 / 2750〜 | 紫檀 |

級は100点刻み、段は150点刻み（降格が無いぶん上位を安売りにしないため）。
**全ランクが必ず2文字**（`3級` / `初段`）。10級以下を作ると「15級」で3文字になり、駒型バッジに入らない。
階級の色は3ランクごとに上がるので、**文字を読まなくても強さが伝わる**。

### 降格はしない

- 段級位は**これまでの最高到達点**（`best_rank`）を出し続ける
- 実力値の数字だけは正直に上下させる（ここまで固定すると何も動かない画面になる）
- 実力値が今の段級位の下限を割っているあいだは、次までのゲージを **0% で止める**（マイナスを出さない）

🟡 **承知のうえの副作用**: 降格が無いうえに §2 の `lossGuard` が負けのぶんだけ点数を注ぎ足すので、
**集団全体が上へ流れる**。500人・実力ばらつきσ=200のシミュレーションでは:

| 1人あたり | 5級のまま | 初段以上 | 六段 |
|---|---|---|---|
| 10局 | 41% | 0% | 0% |
| 20局 | 23% | 3% | 0% |
| 40局 | 15% | 23% | 0% |
| 300局 | 5% | 72% | **19%** |
| 600局 | 4% | 83% | **32%** |

🔴 **たくさん指す人はいずれ六段に届く**（`lossGuard` が無ければ300局で3%）。
本番の実績は1人あたり平均5.8局・最多40局（2026-08-27）なので当分は関係ないが、
**段級位は降格しないので、増えてから締めても戻せない**。
逃げ道は**七段以上を足すこと**（`RANKS` に行を足すだけ。既存の `best_rank` は壊れない）。
締めたくなったら ①段の刻みを広げる ②`lossGuard` の3点を弱める、で後から調整できる
（**どちらも `src/worker/rating.ts` の1か所**）。

## 4. どの対局が反映されるか

| 対局 | 反映 |
|---|---|
| だれかと対戦（人間相手） | **100%**。終わり方は問わない（詰み・投了・時間切れ・切断負けすべて同じ扱い） |
| 千日手・連続王手の千日手・両者切断 | 引き分けとして反映（同格なら両者0） |
| COM戦（60秒待って相手が居なかったとき） | **段級位が1級以下のあいだだけ・変動は半分** |
| 友達対戦（`invite`） | 反映しない。バッジも出さない |
| チュートリアル | 反映しない |

### 同じ相手との連戦（その日ぶん）

| 何局目 | 変動 |
|---|---|
| 1〜2局目 | そのまま |
| 3局目 | 半分 |
| 4局目 | 4分の1 |
| 5局目以降 | **最小値（±1）** |

- 「変動なし」にしないのは、何も動かないと理由が分からず気持ちが悪いため
- 勝ちも負けも同じように小さくする（片方だけ小さいとそこが抜け道になる）
- **画面に理由は出さない**（普通の人が目にすることはまず無い）

## 5. COM戦のチート対策 — 5段構え

COM戦はブラウザの中だけで進み、**サーバーは結果を知らない**。放っておくと
「対局せずに勝ちだけ申告する」ことができてしまう。

| | 対策 | 効き目 |
|---|---|---|
| ① | **棋譜をサーバーで検証**。勝ちの申告は指し手を全部送ってもらい、`src/kifu/replay.ts` の `replayUsiMoves()` が初期局面から1手ずつ合法手チェックしながら並べ直し、最後が本当に詰みかを確認する | 一番効く。**通信対戦とまったく同じ engine を通る**ので、クライアントだけが知っている抜け道は原理的に作れない |
| ② | **勝ちだけ検証**。負け・引き分けは自己申告のまま受ける | 損する方向に嘘をつく動機が無い |
| ③ | **1回きりの引換券**。60秒待ってCOMに切り替わった瞬間に Matchmaker が署名つきの `{jti, uid, exp}` を発行し、報告時に消費する | 🔴 **発行の位置そのものが上限**。キュー参加時に配ると「並んですぐ抜ける」で無限に取れるので、必ず切替の瞬間に出す。1人あたり60秒に1枚 |
| ④ | **手数の下限**（12手） | 雑な捏造だけを弾く保険 |
| ⑤ | **1日の上限**（20局） | 60秒待ちが要るので普通に遊んで届く数ではない（保険） |

🔴 **「発行から60秒以上」の時間条件は入れない。** COMの応手は0.7秒間隔なので、
30手で勝つと25秒前後、50手でも40秒ほどで終わる。**強い人が中級AIを速攻で倒すと普通に60秒を切る**ため、
正当な勝ちを弾いてしまう。③で構造的に縛れているので重複でもある。

これでも「自分で両側を指して短い詰みを作る」ことは理屈上できるが、**COM戦で届く上限は1級**なので
初段より上は人と戦って勝つしかない。難易度も自己申告だが、上限を1級相当にしてあるので
「超級と嘘をついても届く先は変わらない」。

🟡 **正直に負けを送る人だけが下がる**構図は残る（申告しなければ下がらない）。
COM戦の上限が1級なので影響は頭打ちと判断して受け入れる。

### COM側の実力値（表示スケール）

初級 1400 / 中級 1600 / 上級 1750 / 超級以上 1900。

🟡 `/online/` ではCOMの強さを選べず、**AI対戦ページで最後に選んだ難易度**がそのまま使われる
（`getStandardAiDifficulty()`。やねうら王級は `super` に丸め）。しかも初回ロードで
`shogi_ai_difficulty` に `medium` が自動保存されるので、**実際にはほとんどの人が「中級=1600」固定**になる。

## 6. 保存（D1・`migrations/0003_player_rating.sql`）

`player_rating`（1人1行）と `rated_game`（1局1行）の**2枚だけ**。

`rated_game` は主キー `game_key`（対人=`room_code` / COM戦=券の`jti`）で**3つの役目を兼ねる**。

1. **二重適用の防止** — 実力値更新は必ず `batch([INSERT rated_game, UPSERT player_rating ...])` の
   1トランザクションで撃つ。D1 の batch は SQL トランザクションなので、
   主キー衝突でバッチごと失敗し1点も動かない。DO alarm の再実行も、COM戦の券の再送も、これ1つで弾ける
2. **同じ相手とのその日の連戦数** — `COUNT(pair_key, played_on)`
3. **COM戦の1日の上限** — 同じ COUNT を `pair_key='<uid>|COM'` で

判定に要るのは当日ぶんと券の有効期間（2時間）だけなので、**書き込みの一部で確率的に古い行を間引く**。

「その日」の区切りは**日本時間**（`jstDateKey`）。

## 7. 終局処理は `finalizeGameOver` の1か所だけ

`match_room.ts` の終局の**書き込み**は4か所に分かれたまま（詰み・千日手は `handleMove`、投了は
`handleResign`、時間切れは `finalizeTimeout`、切断負けは `finalizeDisconnect`）。
どれも `UPDATE → loadRow → finalizeGameOver → broadcastState` の順で通す決まりにしてあり、
**実力値を動かすのはこの1か所だけ**。終局のパスを増やすときは broadcast の前にここを呼ぶこと。

🔴 **実力値が付かなくても対局結果は必ず配る。** D1 の失敗をここで投げると勝敗そのものが相手に届かない。
例外は飲んで、変動なしで先へ進める。時間切れ・切断負けは `alarm()` からも来るので
`ctx.waitUntil` は使えず、DO の中で `await` する。

## 8. 画面のどこに出るか

| 場所 | 形 | 中身 |
|---|---|---|
| ロビー | 駒型バッジ | 段級位・実力値・次までのゲージ |
| マッチング成立 | 色つきタグ | 相手の段級位だけ（**実力値の数値は出さない**） |
| 対局結果 | 段位カード（駒型バッジ＋数字＋ゲージ） | 段級位・実力値と変動幅・次の段級位までの残り。昇級/昇段したときはカードごと金色になり、下の「昇級・昇段した対局だけの演出」が動く |

- **自分の実力値数値は出す／相手は段級位だけ**
- 🔴 対局結果の**ゲージだけは対局データ（`MatchPayload`）に入っていない**。
  `/status?uid=` と COM戦の `/bot-result` が返す `RatingView` だけが持つ値なので、
  終局直後の `refreshStats({ withRating: true })` の返事で `applyResultRankProgress()` が後から埋める。
  返事を待つあいだ盤が下へずれないよう、ゲージ行は**高さを先に確保して `visibility` で隠す**
- 🔴 **対局中の対局者バーには段級位を出さない**（2026-08-27 に削除）。指している最中に格付けを
  見せないための判断で、`MatchPayload` の `sente_rank` / `gote_rank` 自体は結果画面が使うので残っている
- 🔴 ロビーのカードは**HTMLに最初から置き**、localStorage の控えで同期的に埋めてから
  サーバーの値で数字だけ差し替える。後から DOM を挿すと CTA が下へずれて CLS/LCP が悪化する
- 🔴 CTAのメタ行（`#mm-cta-meta-text`）に段級位を混ぜない。`applyStats()` と `refreshGateUi()` の
  2か所が `innerHTML` を上書きするので消える

段級位の受け渡しは**添字だけ**（`0`〜`14`）。ラベルと色はクライアント側（`shogi.js` の
`ONLINE_RANK_LABELS`）で付ける。**サーバーの `RANKS` と並びが一対一**なので、片方だけ増やさないこと。

### 「段級位・実力値を表示しない」設定（2026-08-27）

詳細設定のチェック、またはロビーの段位カード右上の×から切り替える。保存は端末ごと
（localStorage の `shogi_rank_hidden`。`shogi.js` の `isRankHidden()` / `setRankHidden()` が正本）。

- ONのあいだは**自分の段級位も相手の段級位も出さない**。上の表の3か所すべてが消える
- **点数の計算は普通に続く**。非表示にしている人と当たった相手の実力値も通常どおり増減する
- 出口は2重にしてある。①クライアント: `createRankBadge()` が `null` を返す
  ②サーバー: キューに `?hr=1` を付けると `Matchmaker.pairUp()` が**その人の段級位を `null` にする**
  （相手の `matched` に渡さない・`MatchRoom` にも預けない、が1か所で済む）
- 🔴 ロビーのカードは HTML に直書きなので、**`index.html` 先頭のインラインscript**が
  `<html class="rank-hidden">` を付けて消す。defer の `shogi.js` まで待つと CTA が上へ跳ねる
- 🔴 結果画面は `renderResultRankCard()` の入口で止める。**昇級・昇段のカットインもこの中**なので、
  カードだけ消すと「見たくない人に昇段演出が出る」
- 🟡 終局時に `finalizeGameOver()` が両者の段級位を `MatchPayload` に書き戻すため、
  **通信の中身からは消えない**（画面には出ない）。人ごとに payload を作り分けるコストに見合わないので受け入れる
- ×のトーストは**高さ0の入れ物（`#mm-toast-slot`）から浮かせる**。画面下に固定すると
  PCのアンカー広告に重なるうえ、消えたときにレイアウトが動く。
  読み上げのため `role="status"` は**入れ物側**に置く（組み立て終えた要素ごと挿すと変化と見なされない）
- 🟡 **既知の割り切り**: `hr` はキューに並ぶときのURLにしか乗らないので、**並んでいる最中**に
  詳細設定で切り替えても、その1局には反映されない（相手の「見つかりました」画面に1.5秒だけ出る）。
  直すにはキューを張り直すことになり、FIFOの順番とCOM切替の60秒がリセットされるほうが損なので受け入れる

### 昇級・昇段した対局だけの演出

数十局に1回しか起きない瞬間なので、ここだけ**結果ではなく変化を見せる**。
台本は `shogi.js` の `startPromotionSequence`、見た目は `style.css` の「昇級・昇段の演出」。
中心は**駒が成る（裏返る）**こと。段級位バッジをそのまま将棋の駒として裏返す。

| | 内容 |
|---|---|
| ① カード内（毎回・約1.6秒） | 昇格前の姿でカードを出す → 実力値が数字を回しながら上がり、ゲージが右端まで伸びる → 一拍おいて**駒が裏返る**／カードが金になる／光が一閃／「昇段」の落款 → ゲージが次の段級位ぶんに引き直される |
| ② カットイン（**階級が変わるときだけ**・約2.6秒） | 全画面が暗転し、大きな駒が下から飛び込む → 溜め → 裏返って閃光・光条・紙吹雪 → 「昇段」の金帯。タップでスキップできる |
| ③ 見出しの主役交代 | 「あなたの勝利！」→「初段に昇段！」。勝敗は下の行へ落とす。ボタンは「この勢いでもう1局」、シェアボタンを光らせる |

- ②が出るのは**バッジの色（階級）が変わる4回だけ**（6級・3級・初段・四段）。
  毎回やると「早く結果を見せろ」に変わるので、回数を絞ることがそのまま演出の価値になる
- **サーバーの変更は要らない。** 昇格前の段級位は「新しい段級位のひとつ下」で確定する
  （1勝で最大 +37 点・刻みは100〜150点なので、1局で2つ上がることはない）。
  昇格前の実力値は `rating - delta`、昇格前のゲージは直前に届いた `RatingView`（`lastRatingView`）
- 🔴 演出中に届いた `RatingView` は**その場で書かずに溜める**（`promoAnim.pendingView`）。
  途中で新しい値が入ると「ゲージが伸びきる」が飛んでしまう
- 🔴 `prefers-reduced-motion` のときは演出を丸ごと飛ばし、今までどおり結果だけを置く
- 🔴 落款（「昇段」の判子）の位置は動かさない。内側に寄せると「実力値」の見出しに重なり、
  外へ出しすぎるとダイアログ（`overflow:hidden`）に切られる。スマホの余白は18px
- 🔴 カットインの光条は `repeating-conic-gradient`。`conic-gradient` は繰り返さないので、
  1本ぶんだけ書くと**細い棒が1本回っているだけ**の絵になる
- 🔴 駒の影は駒そのものに掛ける。`.rank-flip` や親に `filter` を置くと `preserve-3d` が打ち消され、
  裏返しても表の文字が鏡文字で見えたままになる
- 🔴 カットインの暗転は `requestAnimationFrame` で始めない。裏に回ったタブでは呼ばれるのが遅れ、
  暗転しきらないまま結果が透けて見える

## 9. マッチングは変えない

**実力値はマッチングに使わない。** 先着順（FIFO）のまま、60秒でCOMに切り替わる仕組みもそのまま。
理由: いま同時に待っている人が少ないので、実力値で絞ると成立しなくなる。まず人数を増やすほうが先。

将来、同時に3人以上待つのが当たり前になったら、待ち時間を増やさない範囲で
「実力値が近い2人から組む」を検討できる。

## 10. 識別子

鍵は既存の `uid`（localStorage の `shogi_online_uid`）。**今の仕組みは一切変えない**
（これは再接続の合鍵も兼ねているので、置き換えると進行中の対局が戻れなくなる）。

🟡 ブラウザのデータを消す・機種変・別ブラウザでは実力値が引き継げない。
引き継ぎコードは作らない（使う人がごく少ない一方でロビーの画面が重くなる）。
本格的なログインを足すときにまとめて解く。

参考: リバーシWebのゲスト識別Cookieは **400日・1日ごとにスライド更新**
（以前は14日で、本番の全ゲスト38,009件がちょうど14日で識別子を失った実績があり修正済み）。
将棋側に持ってくるなら **Cookie名と署名saltを必ず分ける**こと
（リバーシのCookieドメインが `.yuki-lab.com` でサブドメイン共有のため）。
