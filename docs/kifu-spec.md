### 純粋な関数の置き場所 🟢（2026-08-21 決定）

`src/kifu/*.ts` に置き、**`src/worker/shogi_engine.ts`（既存の将棋ルール）を使い回します**。
ルールを書き直さないこと。`createInitialGameState()` / `applyMove()` / `calculateValidMoves()` が
再生・曖昧さ解消・KIF読み込みの合法性チェックに必要なものを全部持っています。

vitest（`test/**/*.spec.ts`）はこの形なら読み込めます（`test/engine.spec.ts` が同じことをしています）。
`shogi.js` は先頭で `document` を触るのでテストからは読み込めません。

```
src/kifu/
  moves.ts     USI文字列 ⇄ Move、マス番号の変換
  url.ts       手順 ⇄ base64url、m の丸め
  replay.ts    USI手順 → 局面の並び（§12 の保存形式もこれを使う）
  notation.ts  ▲７六歩／△同　銀／右左直上寄引／打／成・不成
  kif.ts       KIF書き出し・KIF読み込み・USI/SFEN読み込み・形式の自動判定
  browser.ts   上をまとめる esbuild のエントリ（グローバル `KifuCore`）
```

**ページ構成（`defer` のクラシックスクリプト2本）は変えません。**
`build.sh` が `src/kifu/browser.ts` を esbuild の IIFE に束ね、**`shogi.js` の後ろに連結**してから
既存の sed → minify → ハッシュの流れに乗せます。`<script>` は増えません。

- 🔴 **連結は `shogi.js` が先、束ねたものが後**。逆にすると esbuild が出す `"use strict"` が
  ファイル先頭のディレクティブになり、`shogi.js` 全体が strict mode に変わります
  （`build.sh` が `--tsconfig-raw='{}'` を付けているのと同じ理由）。

## 4. 一行バー（閉じているとき）

いまの `#footer-info`（「手番: ／ 手数: 」）を置き換えます。**高さは46px固定**、初期状態は閉じたまま。

```
┌───────────────────────────────────────────────────┐
│ ⌄ 棋譜  26手目: △同飛           手番：あなた │
└───────────────────────────────────────────────────┘
  ↑   ↑     ↑       ↑                  ↑
  開閉 何の欄か 手数  直前に指された手      次の手番
              （左＝過去）                （右＝今）
```

- **コロンが番号と手を結びつける**のが要点です。これが無いと「26手目」が指し終わった手なのか
  これから指す手なのか読めません。「26手目まで」のような言い回しは使いません。
- 先頭に **`棋譜`** と入れて、この一行が何の欄なのかを名乗らせます（2026-08-22 変更。無印だと何のバーか分からない、という指摘）。
- 手番は盤の左右の札にも出ているので、ここでは**小さく添えるだけ**（`手番：あなた`）。
- 🟢 手番の呼び方はモードで変える（2026-08-22 変更）。`先手` とだけ出しても、それが自分なのか
  相手なのかが分からないため（AI対戦は後手を選べる／通信対戦は相手が先手のこともある）。
  実装は `kifuBarTurnLabel()` 1か所。

  | モード | 出す言葉 |
  |---|---|
  | AI対戦 `/` | `あなた` / `AI` |
  | 通信対戦 `/online/` | `あなた` / `相手`（席が決まる前は先手・後手） |
  | 将棋盤 `/board/`（1台で2人） | `先手` / `後手` |
  | 共有された棋譜を眺めているとき | `先手` / `後手`（他人の対局なので） |

  終局後（`gameOver`）は「手番：」ごと消して **`対局終了`** とだけ出す。「手番：あなた」のままだと、まだ指せるように読めるため。＜＞で途中の局面に戻れば手番の表示に戻る。
- **区切りの縦線は入れません**（2026-08-22 変更。線が多いと一行が窮屈に見えるため）。過去と今は左右の位置と余白だけで分けます。
- 行まるごとが押せます。シェブロンは**バーの先頭（左端）**、`棋譜` の左に置きます（2026-08-22 変更）。**閉じているとき下向き**、開くと上向きに変わります（右向きだと「別のページへ移動する」に見えるため）。
- 押した瞬間に背景が沈むフィードバックを入れてください（46pxは指で押しやすい最小サイズ）。
- 開始局面のときは `0手目:` ではなく「開始局面」とだけ出します。

## 5. 棋譜一覧（開いたとき）

- **その場で下に開きます**（全画面モーダルにしない）。盤を上に残したまま手をタップして飛べるようにするため。
- **2列**（左＝先手、右＝後手）。同じ枠の高さで約12手ぶんが見えます。
- **「開始局面」の行は作りません。**
- 🟢 **まだ1手も指していないときは「まだ棋譜がありません」と出します**（2026-08-23 決定）。行が1つもないと空の枠だけが残り、壊れているように見えるため。
- 現在の手を強調し、開いたときはその行が見える位置までスクロールします。
- 行をタップ → その局面へ。
- 行のタップは **＜＞ と同じ扱い**にします。どちらも全局面に止まれるよう仕様を変えます（§10）。
- 一覧の下に **共有・出力 / 読み込み** の2ボタン。
  - 🟢 「共有する」と「書き出し」は開く画面が同じ（共有シート1枚）なので、**1つに統合**しました（2026-08-22 決定）。
  - 🟢 アイコンは **紙（棋譜）＋矢印**で、向きを正反対にします。出力＝矢印が紙の外へ／読み込み＝矢印が紙の中へ。
    下向き矢印どうしだと「書き出し」がインポートに見える、という指摘を受けての変更です。
  - 🟢 **まだ1手も指していないうちは「共有・出力」を出しません**（2026-08-23 決定）。空の棋譜を共有しても
    中身のないURLになるだけのため。残った「読み込み」は横いっぱいにします。判定は**この対局の総手数**で、
    手が進んだあとに ＜ で開始局面まで戻ったときは出したままにします（共有できる棋譜はあるため）。
- 🔴 **アイコンは絵文字を使わないこと。** SVGで描きます。既存のアイコン（メニュー・歯車・詰将棋の各種）と
  同じ線の描き方（`stroke-width` 1.9〜2.2 / `stroke-linecap: round`）に合わせてください。モックにそのまま使えるものが入っています。

### モード別の扱い

| モード | 棋譜バー |
|---|---|
| AI対戦 `/` ・ 将棋盤 `/board/` | フル機能 |
| 通信対戦 `/online/` | **表示と共有のみ**（ジャンプ不可・読み込み不可）。対局中に戻れてはいけないため |
| 詰将棋 `/tsume/` | 第1弾では出さない |

🔴 **通信対戦の指し手はサーバーから取ること。**（2026-08-22 追記。実装時に踏んだ穴）
通信対戦は盤をサーバーの状態で丸ごと置き換えるだけなので、手元の `usiMoveHistory` も
`moveHistory` も**一切育ちません**。ここを見にいくと、何手進んでも棋譜バーは「開始局面」のまま、
共有URLは空の棋譜（`?k=AQ`）、KIFはヘッダだけ、という壊れ方をします。
指し手は `onlineState.usiMoves`（`applyOnlineMatch()` がサーバーの `state.usiMoveHistory` を入れる）
から取ります。入口は `kifuAllMoves()` / `kifuTotalPlies()` / `kifuCurrentPly()` の3つだけです。
🔴 `onlineState.usiMoves` への代入は**描画より前**に置くこと（後ろだと1手ぶん遅れて表示されます）。
また自分の手を先読み表示したときは `updateInfo()` を通らないので、`applyOnlineMatch()` から
`renderKifuBar()` を直接呼んでいます。

🟢 詰将棋ページでは、いまの `#footer-info`（「手番: ／ 手数: 」）を**そのまま残します**（2026-08-21 決定）。
棋譜バーを出さないモードなので、消すと手番・手数の表示が丸ごと無くなってしまうためです。
`#footer-info` と `#kifu-bar` の両方をHTMLに置き、`body.mode-tsume` かどうかで出し分けます。

対局終了ダイアログの「棋譜を見る」（`index.html:675`）を押したときは、
ダイアログを閉じたうえで**棋譜バーを開いた状態**にします。今は閉じるだけなので、ここは約束を果たす形になります。

## 6. 共有URLの仕様

### 形

```
https://shogi.yuki-lab.com/?k=<base64url>&m=<手数>
```

**新しいページは作りません。** 今のページ（`/` = AI対戦）で `?k=` を受けます。
`/kifu/` を作る案は検討して見送りました（理由は §15 の決定履歴）。

### `k` の中身

- 先頭1バイト＝**書式バージョン**（`1`）。将来の変更に備えて必ず入れてください。
- 以降、**1手2バイト**。1手を15ビットに詰めます。

| ビット | 内容 |
|---|---|
| 上位7 | 移動元。マス番号 0〜80、**駒を打つときは 81〜87**（歩・香・桂・銀・金・角・飛の順） |
| 中位7 | 移動先。マス番号 0〜80 |
| 下位1 | 成るなら1 |

マス番号は `(rank * 9) + (9 - file)`（USIの `7g` なら rank=`g`→6、file=7 → `6*9 + 2 = 56`）。
`toUsiMoveString()` が吐く文字列から素直に変換できます。

- バイト列を **base64url**（`+`→`-`、`/`→`_`、末尾の `=` は削除）にして載せます。
- 🔴 **圧縮はしないでください。** 実測で126バイト→128バイトと増えました。すでに無駄がないところまで詰まっています。

### `m` の中身

- 開いたときに表示する手数。省略時は最終手。
- 範囲外の値は最終手に丸めます（エラーにしない）。
- 共有シートを開いたときに見ている局面の手数をそのまま入れます。

### 長さ（心配は不要）

120手で355文字、200手で571文字。Cloudflareの上限16,384文字に対して**3.5%**です。

### `?k=` で開いたときの挙動

- 「共有された棋譜」の見出しを出します（モックの⑤）。
  - 🟢 **モードタブは出したままにします**（2026-08-22 変更）。以前は隠していましたが、
    共有リンクを踏んだ人がこのページから他モードへ移れず、行き止まりになっていたためです。
    ただし**「選択中」の強調（色・下線）は外します**。`/?k=` で「AI対戦」タブが光っていると
    押せるものに見えず、自分の対局に戻る道として機能しないため。押せば `href="/"` へ普通に遷移します。
  - 🟢 見出しはモードタブの**すぐ下**に置きます。タブの位置が通常画面と揃い、棋譜を開いても動きません。
  - 🟢 見出しは**通知バー**で、右端に **［対局設定］ボタン**を置きます（2026-08-22 変更。§11）。
  - 🟢 副題には「◯手・駒を動かすと◯手目から指せます」と出し、**ボタンを押さなくても指し始められる**ことを教えます。
  - 🟢 見出しの副題は **「◯手」だけ**にします（2026-08-21 決定）。モックにある「AI対戦・中級 ／ 日付」は
    `k` に入っていない情報なので出しません。
  - 🟢 盤の向きは**必ず先手側**にします。`aiPlayerSide` の保存値で他人の棋譜が上下逆に出ないように。
  - 🟢 見出しや難易度パネルの出し分けは `shogi.js` の**トップレベル**で `body.kifu-shared` を付けて行います。
    `defer` は最初の描画より前に走るので、パネルが一瞬見えてから消える事故を避けられます。
    🔴 このCSSは `index.html` の Critical CSS に置くこと。`style.css` に移すとチラつきます。
- 棋譜バーは**開いた状態**で表示します。この人は棋譜を見に来ているので。
- 🔴 **眺めている間は対局の保存に触らないこと**（§12）。棋譜を見ただけで遊びかけの対局が消える事故を防ぎます。
- 読めない `k` のときは、エラーで止めずに「棋譜を読み取れませんでした」と出し、
  ふつうの対局画面に落とします。切れたリンクを踏んだ人を行き止まりにしない。

### QRコード 🟢 第1弾では出しません（2026-08-21 決定）

共有シートは「リンクをコピー / X / LINE」の3つだけにします。棋譜URLは200〜600文字と長く、
QRのマス目が細かくなりすぎる（120手でM=73マス角、200手でM=93マス角）ため、スマホ画面での
読み取りやすさに不安が残る、という判断です。

あとから足すときのために調べたことは残しておきます：`qrcode.js` の**誤り訂正レベルを明示指定**すること
（既定のHは長さによって失敗します。§2参照）。実測のサイズは120手でH=97マス角／M=73／L=65、
200手でH=121／M=93／L=81で、**Mが妥当**です。生成失敗は `try/catch` で拾って落ちない作りにします。
既存の招待QR（`openFriendQrModal()`）が既にレベルMで動いているので、そのまま真似できます。

### 対局終了ダイアログの共有 🟢 棋譜付きURLにする（2026-08-22 追加）

対局が終わった瞬間がいちばん共有される場面なので、結果ダイアログの
X・Facebook・LINE・リンクコピーの共有先を **`/?k=…&m=<最終手>`** に差し替えます。
作れないとき（0手・`KifuCore` 無し・エンコード失敗）だけ、今まで通り今見ているページのURLに落とします。

文面（`buildResultShareText()`）:

```
将棋Webで対局しました！（63手・詰みで先手の勝ち）

▼ 棋譜はこちら
https://shogi.yuki-lab.com/?k=…&m=63

#将棋Web
```

- 1行目は `（◯手・◯◯で◯の勝ち）`。終局理由が無い／`終局` のときは理由ごと省きます。
- 勝敗は**先手／後手のまま**（第三者が読むので、「あなた」「◯◯さん」にはしない）。
- 🔴 **X には `url` パラメータを使わず、本文にURLを入れます。** `text` と `url` の連結のされ方に
  依存すると「▼ 棋譜はこちら」とURLが離れる可能性があるためです。カードは本文中のURLからも出ます。
- LINE は本文を `text`、URLを `url` に渡します（LINEが末尾に付ける）。1対1のトークなのでハッシュタグは付けません。
- Facebook は本文パラメータを無視するので `u` にURLを渡すだけです。
- 棋譜バーの共有シート（`shareKifuTo()`）も同じ形にします。見出しだけ
  「棋譜」の重複を避けて `将棋Webで指した将棋（◯手）` にします。

#### 🔴 通信対戦だけは指し手が手元にない

通信対戦は盤をサーバーの状態で置き換えるだけなので、`usiMoveHistory` が手元で育ちません
（COM戦・チュートリアルのローカル対局は `finalizeMove()` を通るので手元に揃います）。
サーバーは毎回の応答に `match.state.usiMoveHistory` を載せて送ってきているので、
`applyOnlineMatch()` でこれを `onlineState.usiMoves` に取っておき、共有はそこから作ります。

- 🔴 `applyOptimisticMove()` / `rollbackOptimisticMove()` では触りません。
  `onlineState.usiMoves` は**サーバーが確定した手だけ**を持つ変数にします（先読み表示のズレを持ち込まない）。
  共有は終局後にしか使わないので、1手ぶんの遅れは問題になりません。

## 7. 棋譜の表記（▲７六歩）

一覧と書き出しの両方で使います。**ここが第1弾でいちばん手間がかかる部分**です。

- `▲`＝先手 / `△`＝後手、筋は全角数字、段は漢数字（`▲７六歩`）。
- 直前の手と同じマスなら `同`（`▲同　銀`。慣例で全角スペースを1つ入れます）。
- 成るときは `成`、成らないときに明示が要る場面は `不成`、打つときは `打`。
- 🔴 **同じ種類の駒が同じマスへ行けるときは `右 / 左 / 直 / 上 / 寄 / 引` で区別する**必要があります。
  これが無いと一覧に同じ表記が並んで読めません。合法手生成は既にあるので、それを使って
  「同じマスへ行ける同種の自駒が他にあるか」を調べて付けます。

なお **KIF書き出しには曖昧さ解消は要りません**。KIFは移動元を括弧で書く形式（`７六歩(77)`）だからです。

## 9. 読み込み（貼り付け）

- 入口は**棋譜バーの「読み込み」ボタン1か所だけ**です。
  🔴 左上メニューには置きません（2026-08-22 変更。以前は置いていました）。左上メニューは
  詰将棋ページ・通信対戦ページにも出るため、そこから読み込むと**他人の盤（サーバーが持つ局面）や
  詰将棋の問題が置き換わって壊れます**。棋譜バーはモードごとに出し分けられるので、
  入口をそちらへ寄せてあります。通信対戦では棋譜バーの「読み込み」も隠します
  （`canImportKifu()` と `body.mode-online #kifu-action-import`）。
- **形式は自動で見分けます。** 貼られた瞬間に「KIF形式・26手」のように出して、読み込む前に安心させます。

| 形式 | 判定の手がかり | 対応 |
|---|---|---|
| KIF | `手数----指手` の行、または `７六歩(77)` の形 | ✅ |
| USI / SFEN | `position startpos moves …`、`startpos moves …`、または `7g7f 8c8d …` の羅列 | ✅ |

- KIFの `変化：` 以降は読みません（本譜だけ）。
- 🔴 **黙って失敗しないこと。** 読めないときは必ず理由を出します（「KI2形式には未対応です」など）。

  （2026-08-22 追加。ボタンも共有リンクと同じ［対局設定］）。
- 🟢 対局終了ダイアログにある既存のX・Facebook・LINE・リンクコピーは、**共有先を棋譜付きURLに差し替えました**（2026-08-22 変更。§6）。当初は「今回は変えない」としていましたが、いちばん人が共有したくなる場面につながっていないため撤回しました。

## 10. 履歴移動の仕様変更（＜＞と棋譜一覧を同じ扱いにする）

いまは `findAiModeHistoryTargetIndex()`（`shogi.js:2475`）が、AI対戦の ＜＞ を
「対局中かつ人間の手番の局面」だけに着地させています。AIの手番に止まると操作できなくなるためです。

**変更後：＜＞も棋譜一覧も、全局面に止まれるようにします。**

- `findAiModeHistoryTargetIndex()` の飛ばし処理を廃止し、`historyTargetIndex()` は素直に前後1つを返します。
- ＜＞ の有効・無効は「端に居るかどうか」だけで決めます（`updateHistoryButtons()`）。
- 🔴 **相手（AI）の手番の局面では駒を動かせないので、その局面に着いた時点で理由を出します。**
  - 文言：「ここは相手の手番です。＜ ＞ で自分の手番の局面に移ると指せます」（2026-08-22 変更）
  - 🟢 出すのは **①＜＞や棋譜一覧で着地した瞬間（`restoreState()` の末尾）②駒に触れたとき
    ③その局面のままページを開き直したとき（`bootGame()` の末尾）** の3か所です（2026-08-22 変更。
    以前は②だけでした）。②だけだと、盤に触れない限り「手番：AI なのにAIが指さない」画面のまま
    止まって見えます。実装は `noticeOpponentTurnIfStuck()` の1か所に寄せてあります。
  - 🟢 出すのは **「AI対戦・終局していない・過去の局面を見ている（履歴の末尾でない）」ときだけ**にします
    （2026-08-21 決定）。最新局面でAIが考えている最中は今までどおり黙っています。そこは「思考中」表示の担当で、
    ここで警告を出すと毎手ぶん出てしまうためです。
  - 🟢 棋譜バーを開く処理は**やめました**（2026-08-22 変更）。開いた先にあった「この局面から指す」のボタンが
    無くなったためです。この結果、**自分の対局ではAIの手番の局面から枝分かれできません**。
    自分の手番に戻って指し直す（＝「待った」）は今までどおり動きます。
  - 表示は既存の `setMoveHint()` / `#move-hint`（盤に重ねて4秒で自動的に引っ込む）の仕組みを流用してかまいません。
  - 🔴 ただし **`moveHintEnabled`（詳細設定でOFFにできる「動かせない理由の案内」）のON/OFFに従わせないこと。**
    これは親切な案内ではなく「なぜ動かないのか」の説明なので、OFFにしている人にも必要です。
- 将棋盤モード（`/board/`）はもともと全局面に止まれるので変更なし。
  通信対戦は引き続き ＜＞ 無効（棋譜バーは表示のみ）。

### 🔴 戻った先がAIの手番でも、AIに指させないこと

**過去の局面を見ているだけのときにAIが動き出してはいけません。** いまは `restoreState()` が
AIを起動せず、むしろ思考中のAIを打ち切るので（`shogi.js:2426` 冒頭）、＜＞で戻ってもAIは指しません。
この性質を壊さないでください。

ただし**そのままだと1か所だけ穴が開きます**：

- 過去の局面に戻った状態で**ページを再読み込みする**と、復元処理の最後に `scheduleAIMoveIfNeeded()` が
  呼ばれます（`shogi.js:4671`）。いままでは＜＞がAIの手番に止まれなかったので起きませんでしたが、
  §10 の変更で起きるようになります。

**対処（推奨）**: `scheduleAIMoveIfNeeded()`（`shogi.js:3550`）の先頭に
**「最新の局面に居るときだけ動く」というガードを1つ足してください**（`currentHistoryIndex` が履歴の末尾かどうか）。
呼び出し側を個別に直すより安全で、あとから呼び出しを増やしても壊れません。
新規対局・手を指した直後・「◯手目から指す」の直後は、いずれも末尾にいるので影響しません。

## 11. 途中の局面から指し継ぐ

棋譜の途中の局面から指し継げるようにします。**第1弾に含めます**（2026-08-21 決定）。

### 入口（2か所）🟢 2026-08-22 変更

1. **駒を動かす**（既定の道）。棋譜を見ている最中に盤の駒を動かすか持ち駒を打てば、

棋譜バーを開かないと見えず、気づかれないためです。

### 駒を動かして始めたとき

- 🔴 **どちらの側の駒も動かせるようにします**。`isLocalPlayersTurn()` に
  「棋譜を見ている間は true」の分岐を足します。これが無いと、たまたま `aiPlayerSide` と一致した
  手番の局面でだけ1手指せて、その後AIが返さず固まります（実際に起きていた不具合）。
- **動かした側が「あなた」**になります（`aiPlayerSide` をその側に入れる）。相手はAI・いまの難易度。
- 🟢 **盤は自分側が手前になるよう反転させます**（2026-08-22 決定）。
  無言で回ると事故に見えるので、`showKifuToast()` で
  「26手目から対局を始めました（あなた：後手／AI：中級）」と理由を添えます。
- 切り替えは `finalizeMove()` の**先頭**で行います。`josekiMoveIndex` の判定が `aiPlayerSide` を読むので、
  それより後ろに置いてはいけません。
- 🟢 履歴の切り落としは要りません。直後の `saveCurrentState()` の `slice()` が捨ててくれます。

### ［対局設定］から始めたとき

- 🔴 **見出しには何手目から始まるかを必ず書きます**（「20手目から指す」）。
  どこから始まるか分からないまま対局が始まるのが一番こわいためです。
- 選ぶのは3つ。
  - **あなた**：先手 / 後手
  - **相手**：AIと対戦 / 自分で両方
  - **強さ**：解放済みの難易度から選べます（🟢 2026-08-22 追加。以前は「いまの設定を引き継ぐ」でした）
  - 「その手数より後の◯手は使いません」と明記します。
  - 🔴 難易度は**確定したときにだけ** `aiDifficulty` へ入れます。既存の難易度モーダルのハンドラは

- 確定した瞬間にその局面から対局が始まります。相手の手番ならAIがすぐ指します。

### 開始後

- その手数より後の手を捨てます。**既存の `saveCurrentState()`（`shogi.js:2389`）の `slice()` がやってくれる**ので、
  新しい仕組みは要りません。
- 自分の手番でない側を選んだ場合は、AIがすぐ指します。
- 🔴 **開始時にその場で履歴を切ってください**（2026-08-21 決定）。`moveHistory` / `positionHistory` /
  `checkHistory` を `currentHistoryIndex + 1` で、`usiMoveHistory` を `currentHistoryIndex` で切ります。
  これをやらないと §10 のガード（履歴の末尾に居るときだけAIが動く）に引っかかって**AIが指し始めません**。
- 🟢 **「自分で両方」は `/board/?k=…&m=…&start=1` へ移動**します（2026-08-21 決定）。
  「自分で両方指す」＝将棋盤モードそのものなので、保存先も操作も既存の将棋盤モードのまま使えます。
  AI対戦ページのまま両手番を指せるようにすると「AI対戦ページなのにAIが指さない」という新しい状態が生まれ、
  保存先・難易度表示・終局ダイアログの文言に例外を足すことになります。
  `start=1` が付いているときは閲覧ではなく対局として読み込みます。
- 🟢 **逆向きも作ります**（2026-08-22 追加）。将棋盤ページで棋譜を見ているときに「AIと対戦」を選んだら
  `/?k=…&m=…&start=1` へ移します。モードタブでも AI対戦へは行けますが、それでは**見ている棋譜を持ったまま
  移れない**（タブは `/` へ飛ぶだけで `k=` を落とす）ためです。
  🔴 **新しいURLパラメータは足しません。** 手番（`aiPlayerSide`）と強さ（`aiDifficulty`）は
  移る前に `saveToLocalStorage()` で保存すれば、移動先が読み直してくれます。
- 🔴 **URLから `?k=` と `&m=` を落としてください**（`history.replaceState`）。

- ここから先はふつうの対局です。保存が始まります（§12）。

## 12. 保存の扱い

### 見ているだけの間は保存しない 🟢

`?k=` で開いて棋譜を眺めている間は保存に触りません。**フラグ1つで済みます**（例：`isViewingSharedKifu`）。

🟢 ただし `saveToLocalStorage()`（`shogi.js:4570`）は**関数まるごと早期returnにはしません**（2026-08-21 決定）。
盤面を書く `if (stateKey)` のブロックだけ飛ばします。難易度・駒の表示・手番の好みは、棋譜を見ている間に
変えたのなら保存されてよいためです。

### 指し始めたら、ふつうに保存する 🟢

**駒を動かした瞬間（または［対局設定］で確定した瞬間）にそのフラグを下ろし**、以後はふつうの対局として保存します。
**そのとき前の対局は上書きされます。これで正しく、確認ダイアログは入れません。**
理由は、**既存の「新規対局」ボタンも確認なしで上書きしている**からです
（`handleResetButtonClick()` `shogi.js:4754`）。ここだけ確認を出すと一貫しません。

つまり「保存に触らない」のは**眺めている間だけ**で、指し始めたら普通の対局と同じです。

### 保存の持ち方そのもの ── 第1弾でやります（2026-08-21 再決定）

これは機能の話ではなく、**遊びかけの対局をブラウザに残しておく方式**の話です。

いまは1手指すたびに「盤上の全コマの配置を含む履歴まるごと」を文字列にして保存し直しています。
120手で234KB、保存処理に5.4ms（PC実測。スマホなら20〜40msの見込み）かかり、終盤ほど指したときの反応が鈍ります。
これを「**指し手の並びだけ保存して、開くときに1手ずつ再生して盤を組み直す**」方式に変えると、
1局あたり約700バイトになります。

いったん「第1弾ではやらない」と決めていましたが、**やることに変えました**。理由は、棋譜の実装で
`src/kifu/replay.ts`（指し手の並びから盤を組み立てる処理）がどのみち出来上がるので、
そこに乗せるだけで済むためです。

**新しい保存の形（v2）**

```json
{ "v": 2, "mode": "ai", "moves": ["7g7f", "8c8d", "…"], "at": 26 }
```

`at` は `currentHistoryIndex`（0＝開始局面）。盤・持ち駒・手番・王手・千日手用のハッシュは全部再生で作り直します。

- 🟢 **古いデータの読み替えは簡単です。** 旧形式にも `usiMoveHistory` と `currentHistoryIndex` が
  入っているので、旧形式を見つけたら**その2つを同じ再生に流すだけ**です。変換用の別コードは要りません。
- 🔴 **千日手のハッシュが一致していること。** `shogi.js` の `getBoardHash()` と
  `src/worker/shogi_engine.ts` の `getBoardHash()` は、持ち駒を回す順まで同じです（飛角金銀桂香歩）。
  ここがずれると「再読み込みしたら千日手の判定が変わる」という一番たちの悪い壊れ方をするので、テストで固定します。
- 🔴 **終局フラグは再生で出せます。** AI対戦・将棋盤で `gameOver` になるのは詰みと千日手／連続王手だけで
  （投了ボタンは通信対戦専用）、`applyMove()` がそのまま返してくれます。
- 🔴 **再生に失敗しても落とさないこと。** 例外は握って新規対局に落とします。
- 🟢 古い `shogi.js` に巻き戻したときは、v2 のデータは「履歴なし」と読まれて新規対局になるだけで、例外にはなりません。
- 🟢 **入れる順番**は最後です。棋譜の機能を一通り動かしたあと、独立した1ステップとして入れます
  （同時に入れると、壊れたときにどちらが原因か分からなくなるため）。

### 🔴 1手指すたびに全手数を並べ直さないこと（実測あり）

棋譜の表記も新しい保存形式も「指し手の並びを頭から並べ直す」ことで作ります。素直に書くと
**1手指すたびに全手数を並べ直す**ことになり、120手の局面では**約12ms**かかりました
（旧形式の保存は同じ環境で0.5ms）。終盤ほど指したときの反応が鈍るという、直そうとしていた問題が
そのまま残ります。

そこで `replayUsiMoves()` と `buildNotation()` は**前回の結果を受け取れる**ようにしてあります。
前回の手順が今回の頭とそっくり同じなら、共通部分は飛ばして続きだけ足します。

| 120手の局面で1手足すとき | 実測 |
|---|---|
| 頭から並べ直す | 12.5 ms |
| 続きだけ足す（実装） | **0.10 ms** |
| 保存（v2, JSON化+書き込み） | 0.015 ms |
| 保存（旧形式・比較用） | 0.51 ms / 243,665 バイト |
| 保存（v2） | **878 バイト** |

🔴 **「待った」で戻って別の手を指したときは使い回してはいけません**（別の対局が混ざる）。
頭が一致しているかを必ず確かめること。テストで固定してあります。

## 14. テスト観点

- **URLの往復**：エンコード→デコードで元の手順に戻ること。移動・成り・駒打ちの全種類を含める。
- **KIFの往復**：書き出し→読み込みで元の手順に戻ること。表記の曖昧さ解消（右左直上寄引）もここで効きます。
- 壊れた `k` / 範囲外の `m` / 空文字で落ちないこと。
- 平手以外のKIFを断ること。
- **＜＞と棋譜一覧が、AIの手番の局面にも止まれること**（§10）。
- **その局面で駒に触ると警告が出ること。詳細設定で「動かせない理由の案内」をOFFにしていても出ること**（§10）。
- **途中の局面から指し始めると、その先の手が捨てられること**（§11）。
- 🔴 **棋譜を見ている最中に駒を動かすと、そのまま対局が続くこと**（§11）。先手側・後手側どちらの駒でも
  動かせること。後手側を動かしたら盤が反転すること。AIが返してくること。
- **読めない `k=` で開いたとき、ふつうの対局画面（難易度・新規対局が出て、モードタブが「選択中」に光っている状態）に落ちること**。
  描画前に付ける `body.kifu-shared` を消し忘れると、操作できない画面が残ります。
- **`?k=` で眺めている間もモードタブが出ていて、他モードへ移れること**（§6）。どのタブも光っていないこと。
  駒を動かして対局が始まったら、タブが「選択中」の見た目に戻ること。
- **`?k=` で眺めている間は保存が更新されず、指し始めると更新されること**（§12）。
- 🔴 **過去の局面に戻ってページを再読み込みしても、AIが指し始めないこと**（§10）。
- **保存形式**（§12）：旧形式で保存された対局が続きから復元されること。千日手の判定が再読み込みで変わらないこと。
  壊れたデータで例外を投げず新規対局に落ちること。
- **続きから並べる処理**（§12）：前回の結果を渡しても、頭から並べ直したのと同じ結果になること。
  「待った」で分岐した手順では使い回さないこと。
- **サーバーが組み立てた棋譜が共有URLにできること**（§6）。`src/worker/shogi_engine.ts` の
  `toUsiMoveString()` が吐く文字列を `encodeKifuParam` が受け取れること。通信対戦の共有はこの前提の上に乗っています。
- **対局後の共有**（§6）：AI対戦・将棋盤・通信対戦・COM戦のそれぞれで、結果ダイアログの共有先が
  棋譜付きURLになり、そのURLを開くと同じ手順が最終局面で再生されること。
  0手で終わった対局では「▼ 棋譜はこちら」が出ず、今まで通りサイトURLが共有されること。
- 既存の `npm test`（vitest）に足してください。盤やDOMを触らない純粋な関数（表記変換・URL・KIF）を優先的にテストに載せてください。
